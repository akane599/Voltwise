---
description: How Android work is ticketed, routed and dispatched (Sidequest, routing profile android-kit)
priority: 15
---
- Every code ticket's `--verify` preserves the real command exit status and is scoped to the change. Prefer `bash .claude/kit/gradle-check.sh :<module>:<existingTask>` when the helper exists in the executor checkout; otherwise use raw `./gradlew ...` without a grep/head pipeline. Read-only/docs tickets use an appropriate evidence check, not a fabricated Gradle task. Test design/repairs: behavior-verification (Sol high); run-only checks: test-execution (Luna medium).
- A UI ticket that adds or changes parameters of a screen-level composable also runs `:app:compileDebugAndroidTestKotlin` in its verify: androidTest call sites (e.g. `NowRecoveryDeviceTest`) aren't covered by screenshot tests.
- UI tickets that read new ViewModel state declare that screen's `viewmodel/<X>ViewModel.kt`, `<X>UiState.kt` and `<X>ViewModelTest.kt` up front, with a "logic change needs a test + negative control" clause: the board auto-refuses mid-run scope requests outside the declared files. A UI ticket that adds or changes a screenshot preview also declares `app/src/screenshotTestDefaultDebug/reference/<package path>/<TestFile>Kt/`: AGP stores references there, not under `app/src/screenshotTest/`.
- **UI is Claude-only.** Anything that changes what the user sees (composables, theme and tokens, UI resources, previews, screenshot references) is `interaction-design-implementation`, or `ui.tweak` when it's mechanical. Never file UI under `coding.*`, `debugging` or `experiment.frontier`: those route to GPT. A feature that needs logic and UI becomes two tickets: the logic (`coding.*`) first, the UI ticket `depends-on` it. The UI hook catches Edit/Write and known screenshot-update commands (not arbitrary shell writes); inspect changed paths before integration; when one hands back a UI change, file it as a UI ticket.
- **Hard work is `coding.hard.frontier`** (GPT-6 Astra), not `coding.hard`; experiments are `experiment.frontier`. Sidequest moves Astra off every category whose id lacks "frontier", so its own `coding.hard` and `experiment` are switched off in this profile.
- **Map tickets** (writing `.claude/.codebase-info/`) get a writer only in Sidequest's shared-tree artifact mode: category `codebase-exploration`, `.claude/.codebase-info/` as the only declared file, codebase-mapper's `Shared-tree artifact mode: …` line on a line of its own, dispatched with `sharedTree: true`. Any other shape spawns read-only; follow the codebase-mapper skill's Sidequest handoff, or map inline.
- Other categories: plan review → `plan-review.frontier` (/plan-audit); diff review → `review-audit`; screenshot critique → `visual-evaluation`; defect with an unknown cause → `debugging`.
- **Reviews follow Sidequest's sizing:** bind a read-only `review-audit` (Opus) to a submitted candidate only when its oracle is weak, its consumers stay unchecked, or it's high-stakes; a clear ticket whose verify passes needs none. When you bind one, its description gives the absolute path of `.claude/kit/android-bug-checklist.md`. A rejected candidate gets a fresh repair ticket that starts from a reproducing test.
- Escalation: a ticket that fails or stalls twice on a GPT route gets a new linked `escalation` ticket (Opus) carrying both attempts' evidence. Only if that stalls too: `frontier` (Fable). Neither is ever a first route.
- Gradle is a shared runtime resource: at most 4 tickets whose verify runs Gradle in one wave on this build host (2 elsewhere; 1 on machines under 16 GB). Emulator/adb tickets run one at a time; only the orchestrator boots the emulator.
- Theme/token tickets land before screen tickets (link `depends-on`); two tickets never share a screen or theme file.
- Tickets that need a device say so in the description; everything else must verify on the JVM (unit, Robolectric, screenshot tests).
- Decisions worth keeping (why X over Y) go to PROGRESS.md's decision log when a story is integrated.

- Authentication, SDK/JDK, network and missing-tool failures are environment blockers, not model-quality failures; fix/report them before spending escalation attempts. Change approach between attempts and carry evidence forward. A gateway error after dispatch is not guaranteed to trigger a Claude fallback.
