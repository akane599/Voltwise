## Important

1. **The fallback notice is shown while the user is away from the app** (code-reviewer at 80, silent-failure-hunter at 85; *verified*).
   - `rememberSettingsOpener` (`ui/screens/insights/SettingsPages.kt:72-86`) starts the Settings activity and only then returns the notice text. The callers then show it as a Short snackbar: `InsightsScreen.kt:91,146` and `FindingDetailsScreen.kt:262`.
   - The snackbar's 4 s timer runs while Settings covers the app. The user lands on Settings home with no guidance, which is the case US-25 meant to fix.
   - `UNAVAILABLE` (nothing opened) is unaffected.
   - Fix (UI ticket): show the FALLBACK notices as a `Toast` (`LENGTH_LONG`), which appears over the Settings app. Alternatively, keep the notice and post it as a Long snackbar on the next ON_RESUME.
2. **A refusal on Shizuku or root records nothing** (silent-failure-hunter at 80, pr-test-analyzer; *verified*).
   - `battery/insights/DozeWhitelistReader.kt:21` returns null without a code when `outcome.mode == NONE || DumpOutput.isRefusal(message)`. That guard was copied from `AppStatsRepository`'s ADB path.
   - Here the mode is already SHIZUKU or ROOT, so `mode == NONE` can never be true.
   - A "Permission Denial" from an OEM SELinux policy or a restricted su context is a real failure, yet it leaves the Doze finding frozen with no trace.
   - Fix: delete the guard so every `Failure` records a code. Update the refusal test to expect `ADVANCED_READ_FAILED`.
3. **Doze-whitelist failures show on Status as per-app-statistics failures** (silent-failure-hunter at 85; *verified*).
   - `StatusViewModel.kt:224-225` maps `ADVANCED_READ_FAILED` to "Per-app statistics could not be read" and `ADVANCED_FORMAT_INVALID` to "Android's battery report was not understood". Neither describes a whitelist read.
   - Interleaving these codes with `AppStatsRepository`'s own records also defeats the coalescing of repeated codes in the 60-slot log.
   - This is the cost of reusing those codes, which the earlier review prescribed.
   - Fix: add `DOZE_WHITELIST_READ_FAILED` with its `StatusIssueKind` and en/es/tr strings, or map it to null like `ADVANCED_INCOMPLETE` if it should appear only in the diagnostic report.
