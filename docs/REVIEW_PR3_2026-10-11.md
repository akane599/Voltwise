## Important

1. **The settings fallback crashes on `SecurityException`** (silent-failure-hunter and type-design-analyzer; *verified*).
   - `ui/screens/insights/SettingsPages.kt:26-33` catches only `ActivityNotFoundException`.
   - Some OEM builds throw `SecurityException` for a settings page that isn't exported. When that happens, the chain stops before reaching Settings home, and the exception escapes the `LaunchedEffect`, which crashes the app.
   - Callers: `InsightsScreen.kt:92`, `InsightsScreen.kt:148` (the Turn on snackbar) and `FindingDetailsScreen.kt:114`.
   - Fix: also catch `SecurityException`, and add a test with a context whose first `startActivity` throws.
2. **The Doze-whitelist read fails without any diagnostic** (silent-failure-hunter; *verified*).
   - `battery/insights/DozeWhitelistReader.kt:13-18` maps `Outcome.Failure` and `Readback.Unrecognized` to `null`, exactly like having no access, and records no code.
   - One unknown OEM whitelist kind leaves DOZE_WHITELISTED_DRAINER frozen ACTIVE, and REMOVE_DOZE_WHITELIST is never offered.
   - Fix: add an `onDiagnostic` parameter, wired to `DiagnosticStore::record`. Record `ADVANCED_READ_FAILED` or `ADVANCED_FORMAT_INVALID`. With no access, record nothing (this is the negative control).
3. **`Recommendation` still stores `reversible` and `requiresPrivilege` on their own** (type-design-analyzer; *verified*).
   - `model/InsightModels.kt:147` keeps both flags as stored fields. The UI reads those copies (`InsightsRepository.kt:101`, `FindingDetailsScreen.kt:503`), not `ActionType`.
   - Test fixtures already build contradictory values, e.g. `ENABLE_HIGH_BATTERY_ALERT, false, false` in `DefaultInsightsRepositoryTest`.
   - Fix: `Recommendation(val action: ActionType)` with derived getters. Keep the fields of the stored `RecommendationRow`.
4. **Undo eligibility is written twice** (type-design-analyzer).
   - The checks are `undoable()` in `viewmodel/InsightsRepository.kt:74-77` and its inverse in `InsightActionRepository.undo` at `:129`. They drifted once already, which is why PREPARED had to be added to both.
   - The check also tests `type != FORCE_STOP.name`. As a result, a row whose type name is unknown shows Undo and then fails with `INVALID_JOURNAL`.
   - Fix: one check, based on `enumName<ActionType>(type)?.reversible == true` plus the status.
5. **Test gaps** (pr-test-analyzer):
   - **Fallback chain untested.** The `openSettingsPage` chain and `toIntent` have no tests: the page order, `false` when every page fails, `EXTRA_APP_PACKAGE` vs `package:` data. This needs an androidTest with a throwing `ContextWrapper`.
   - **False-positive lanes bypass the detectors.** `AppAnomalyFalsePositiveTest` calls `ctx.anomaly(...)` directly, so drift in a detector's own floor or window count isn't caught. Run each lane's 4× control through `<Detector>.detect(ctx)`.
   - **No severity control at production share levels.** Add 4× HIGH at a median of about 1.5 through `StuckWakelock` and `BackgroundRunaway` (statistical-detectors rule).
   - **Legacy decode only tested against the current encoder.** The "legacy" `FindingCodec` rows are produced by the current encoder. Add frozen literal v1/v2 JSON strings.

  - `Retention.Days` should `require(days > 0)`.

  - Add a private `changedExternally(row)` helper in place of 7 copied `copy(...)` calls.
- **Wiring default** (pr-test-analyzer). `onDiagnostic = {}` in `SessionSnapshotCollector` would hide a missing Koin wiring. Remove the default so the compiler catches it.
- **Flake risk** (pr-test-analyzer). `InsightsViewModelTest.kt:179` waits on a real `Dispatchers.IO` thread (`ShellRunner.kt:164`). If that regresses, the test hangs until it times out instead of failing an assertion.
